# SilverHamu v0.2.0

SilverHamu brings the embedded transactional database, authenticated TCP service, shared SQL engine, and Windows Owner together under one name. The C ABI and existing database formats remain compatible; the native library filename is now `silverhamu.dll` / `libsilverhamu.so`.

## Owner

- Switch between English and Japanese in Settings. Buttons include icons, query tabs can be closed, and SQL completion covers identifiers and write statements.
- Select and copy cells, ranges, and rows. Column headers stay visible while scrolling, and row numbers stay fixed on the left.
- Choose SELECT 1000 rows, SELECT all, or their editable variants from a table's menu. Edit results above the SQL editor; changes generate UPDATE, INSERT, and DELETE statements for a single execution batch.
- Edit cells inline, including NULL. Pending changes are highlighted. Undo/Redo and removing generated statements restore the table preview. Add, delete, or duplicate selected rows; duplication clears primary and unique key values.
- Browse complete folder query results with page navigation, direct page jumps, and CSV export for all fetched rows, a page, or a row range. Loading animation continues during background reads.

## Folder writes

Folders opened through `.catlink` now support INSERT, UPDATE, DELETE, BEGIN, COMMIT, ROLLBACK, and SAVEPOINT, including editable table tabs.

- Ordinary SQL databases write to their original files. Each transaction can update tables in **one physical database file**; commit or roll back before updating another file.
- PALV archives preserve their format. New segments are written before the catalog is switched atomically. Existing segments remain available for older readers, so updates increase disk usage. Deleting original rows rewrites the table to preserve contiguous row numbering.
- Conflicting archive catalog changes are rejected. Uncommitted archive changes are limited to 128 MiB. Archive metadata does not contain primary/unique constraints, so the archive editor cannot infer or enforce those constraints.
- Full-table editing holds editable rows in memory; prefer 1000-row editing for large tables. Folder DDL is not supported.

## Downloads and setup

- `silverhamu-owner-v0.2.0-windows-x64.zip`: extract the **entire** archive and run `SilverHamu.Owner.exe`. Includes the .NET and Windows App SDK runtimes; Windows x64, Windows 10 version 1809 or later is required. The application is unsigned, so Windows may display an unknown-publisher prompt.
- `silverhamu-v0.2.0-windows-x64.zip`: native library, TCP service, backup/restore utility, and self-contained SQL host. Read the included `README.txt` before starting the service.
- `silverhamu-v0.2.0-linux-x64.tar.gz`: Linux x64 service, native library, backup/restore utility, and self-contained SQL host. Built on Ubuntu 24.04; requires glibc 2.39 or later.
- `silverhamu-0.2.0-linux-amd64-docker.tar.gz`: load with `docker load -i silverhamu-0.2.0-linux-amd64-docker.tar.gz`. Image tag: `silverhamu:0.2.0`. Persist the complete `/data` volume and mount the token file read-only. See [container setup](https://github.com/dhq-boiler/SilverHamu/blob/v0.2.0/docs/service.md#container-operations).
- `SHA256SUMS`: verify downloaded archives against their SHA-256 hashes.

Create a private token file with the included `create-silverhamu-token.py` before starting the service. Never expose a service without authentication. See [service configuration](https://github.com/dhq-boiler/SilverHamu/blob/v0.2.0/docs/service.md), [SQL support](https://github.com/dhq-boiler/SilverHamu/blob/v0.2.0/docs/sql.md), and [Owner usage](https://github.com/dhq-boiler/SilverHamu/blob/v0.2.0/apps/SilverHamu.Owner/README.md).

The six language clients are already published separately at version 0.2.0 in the [client release](https://github.com/dhq-boiler/SilverHamu/releases/tag/clients/v0.2.0). This release does not republish those packages.

The project remains at version 0.x; back up databases before upgrading and account for future API or file-format changes.
