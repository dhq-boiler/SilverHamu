# SilverHamu Owner

SSMSのように、左側でテーブルと列を参照し、右側でSQLを書いて結果を表示する.NET MAUI Windowsデスクトップアプリ。

## 起動と操作

Visual Studio 2026 Communityで `../SilverHamu.Owner.sln` を開き、`SilverHamu.Owner` をスタートアッププロジェクトにしてWindows Machineで起動する。.NET 10とMAUI Windowsワークロードが必要。

初回ビルド前、またはRust側を変更したときはリポジトリルートでネイティブDLLをビルドする。Rustツールチェーンの `cargo` をPATHに設定する。

```powershell
./scripts/build-owner-native.ps1
```

生成先は `target/release/silverhamu.dll`。アプリとテストのビルド時に各出力フォルダーへコピーされる。`SilverHamuNativePath` で互換DLLの場所を明示することもできる。組み込み接続はWindows x64版。

ビルド済みの開発用アプリは `bin/Debug/net10.0-windows10.0.19041.0/win-x64/SilverHamu.Owner.exe`。出力フォルダーの依存ファイルと一緒に利用する。自己完結パッケージ・インストーラーは未作成。

TCP サービスに SQL ホストが設定されている場合は、Owner がサーバーへ SQL 文を送る。KV 専用サービスでは従来どおりクライアントで SQL を実行する。読み取りロールで接続すると、許可されたビューの一覧と照会を利用できる。

サービス接続の通信処理には、NuGetの `SilverHamu.Client` **0.2.0** を使用する。Ownerとテストのビルド時に公開パッケージを復元する。組み込みDBへの直接接続には従来どおりネイティブDLLを使用する。

実サービスには「サービス接続…」からホスト・ポート・トークンを入力するか、トークンファイルのフルパスを指定する。既定は `127.0.0.1:7400`。認証トークンは設定ファイルへ保存しない。サービス起動は [サービスの起動手順](../../docs/service.md) を参照。

処理中は画面中央にハムスターの回し車GIFと「処理中…」を表示し、完了・エラー時に閉じる。元のGIFを起動時にフレームへ展開し、各コマの表示時間を保って処理完了まで繰り返す。ファイル選択の入力待ちには表示しない。Windowsのアニメーション設定が無効の場合は先頭コマを静止表示する。

### 組み込みsilverhamuへの直接接続

- 「DBファイルを開く…」で既存の silverhamu データベース（*.ndb）を指定する。フルパスを入力するか、「参照…」でファイルを選んで「決定」を押す。
- 同じ画面で `.catlink`（旧名 `catdb-current.txt`）も開ける。リンクには相対パスを1行で記述する。`data/main.ndb` ならその DB を開く。`data` のようにフォルダーを指定すると、書庫のテーブル定義（通常の SQL データベースでは各 DB のカタログ）からテーブル一覧を表示する。左のテーブル名を選ぶと、その列名とデータ行を最大100行ずつ閲覧できる。閲覧には一時コピーを使う。書庫にも silverhamu の SELECT を実行できる。例: `SELECT * FROM Book_3 WHERE PublishDate IS NOT NULL`。列の選択、絞り込み、並べ替え、集計、JOIN、IN サブクエリに対応する。SQL で比較・集計する際はプレビュー省略前の値を使う。
- 「新規DB…」で新しいファイルを作る（初期ファイル名はsilverhamu.ndb）。親フォルダーは事前に作成し、既存ファイルは上書きしない。
- フォルダーで単一の `SELECT * FROM Book_3;` を実行すると、暗黙の4096行制限を適用せず結果を最後まで取得する。全件取得が完了してから100行ずつ表示し、「前へ」「次へ」「最終ページ」で取得済みの結果を閲覧できる。全件数・行番号・ページ位置を表示し、フッターの「全件取得」時間は読み取り・SQL評価・一時ファイル保存までの実測値。ページ移動では元の書庫を読み直さず、取得時間も更新しない。結果はメモリ使用量を抑えるため一時ファイルへ保存し、再実行・一覧表示・接続解除・終了時に削除する。`FETCH FIRST n ROWS ONLY` を指定した場合はその件数まで取得する。途中からの範囲指定は `OFFSET n ROWS FETCH NEXT m ROWS ONLY` を使う。`LIMIT` と `TOP` は互換構文として受け付ける。結果欄の検索は表示中のページが対象。CSV出力は取得済み全件・現在ページ・行番号範囲から選べる。並べ替え・集計には既存の128 MiB中間メモリ制限、JOINやCTE等には既存の4096行中間結果制限があり、超過時はエラーとなる。

- フォルダーを開いた状態で `ANALYZE Book_3;` を実行すると、その閲覧中に使う統計をメモリに収集する。大きな分割書庫では一部の行をサンプリングする。書庫ファイルは更新せず、閉じると統計は破棄する。
- `EXPLAIN SELECT * FROM Book_3 WHERE PublishDate IS NOT NULL FETCH FIRST 10 ROWS ONLY;` は実行計画を表示する。`EXPLAIN ANALYZE SELECT * FROM Book_3 WHERE PublishDate IS NOT NULL FETCH FIRST 10 ROWS ONLY;` は同じクエリを実行し、行数・回数・時間を結果グリッドに表示する。
- トークンや常駐サービスは不要。接続種別とファイル名を左側に、フルパスをステータスに表示する。
- SQLの構文・結果表示・確定・取消はサービス接続と共通。接続方式を変更する前に、未確定トランザクションをCOMMITまたはROLLBACKする。
- 「接続解除」では未確定の変更を破棄し、ファイルの所有権を解放する。再接続すると確定済みのテーブルとデータを復元する。
- 使用中のファイルは二重に開かず、使用中であることをエラー表示する。同じファイルをサービスと組み込みで同時に所有する使い方はしない。

SQL表の保存形式はサービス接続と同じで、接続を閉じてから同じDBを別方式で開ける。生のキー値データをSQL表へ自動変換する機能ではない。SQL表の定義がないトランザクションDBはテーブル一覧が空になり、異なるファイル形式はエラーになる。ファイルを開く際のログ復旧は既存silverhamuエンジンが行う。

SQLを入力して「▶ 実行」を押す。テーブル一覧は名前順で、クリックするとそのテーブルを検索する。複数クエリタブ、SQLファイルの保存・読込、結果のCSV出力に対応する。ファイル操作はアプリ内でフルパスを指定し、既存ファイルには上書きしない。CSVは取得結果の全行を出力し、画面の表示フィルターとは独立する。複数SQL文を実行した場合は最後の文の結果を表示し、各文の件数・完了状態をメッセージに表示する。

### フォルダーの更新

フォルダーでも `INSERT`・`UPDATE`・`DELETE` と `BEGIN`・`COMMIT`・`ROLLBACK`、SAVEPOINTを利用できる。テーブルのメニューから「SELECT 1000行して編集」「SELECT 全行して編集」を選ぶと、セル編集・行追加・削除・複製をSQLとして準備し、実行ボタンでまとめて適用できる。実行前の変更は色で示し、Undo / RedoとSQL削除による取消に対応する。BEGIN中の実行は未確定で、COMMITまで元データには確定しない。接続解除・終了時は未確定変更を破棄する。

通常SQL DBの更新は元の `.ndb` へ書き込む。1回のトランザクションで更新できる物理DBは1ファイルで、別ファイルへの更新はCOMMITまたはROLLBACK後に行う。複数のテーブルを持つ同一DB内の更新はまとめて確定できる。フォルダーではDDLに対応しない。

PALV書庫は既存形式を維持し、新しいセグメントを書き終えてから `library.ndb` の目録を1トランザクションで切り替える。更新だけなら対象セグメント、挿入なら追加セグメントを保存し、元行の削除では連続した行番号を維持するため表を再保存する。既存の閲覧接続を壊さないよう旧セグメントは保持するため、更新後はディスク使用量が増える。別接続で目録が変わった場合は上書きせず再接続を要求する。未確定変更は128 MiBまで。書庫形式には主キー・一意制約等の情報がないため、それらの自動補完・制約検証には通常SQL DBを使う。全行編集は全件をメモリ上に保持するため、大きい表では1000行編集や絞り込みを推奨する。

### トランザクション DB の管理

- 「チェックポイント」は組み込み DB または管理者の TCP 接続で実行する。未確定のトランザクションは先に終了する。
- 「キー・値の操作…」は管理者向けの生キー操作。「範囲の値を出力…」は組み込み DB の指定範囲から、値の読み取り用スナップショットを出力する。
- 「バックアップ…」は、開いている組み込み DB の確定状態を新規バックアップに保存する。「新規DBへ復元…」は検証済みのバックアップを新しい DB に復元する。出力先は既存ファイルを指定できない。TCP サーバーのファイルパスを指定して遠隔バックアップを取る機能は含まない。

## 結果の列と長い値

左端の行番号はSQL結果の先頭を1として表示する。絞り込み後も元の結果の行番号を維持する。行番号欄はデータ列とは独立しており、CSVには含めない。行の仮想化にも対応する。

ヘッダーとデータを共通の列幅（初期240px）で区切り、縦横の境界線を表示する。ヘッダー右端の境界を左右へドラッグすると、その列の見出しと全行が同時に広がる・縮まる。境界をダブルクリックすると、見出しと現在表示中の行（表示フィルター適用後）の内容に合わせて自動調整する。境界へキーボードでフォーカスした場合は左右キーで手動調整、Enterで自動調整できる。幅は80～1200px。同じ表の表示フィルター・再選択では幅を保持する。幅の設定はアプリ起動中のみ保持し、アプリ再起動時は初期幅へ戻る。長い値はセル内の1行で末尾を省略し、隣の列へはみ出さない。横に長い表は水平スクロールで確認する。ホバーするとセルの表示値を確認できる。この描画上の省略でデータやCSVの値は変えない。

## 応答性と検証

結果表はWinUI ListView/ItemsStackPanelで行を仮想化し、画面付近の行だけを生成する。絞り込み入力は180msの待機でまとめ、列幅のドラッグ更新は約16ms単位で集約する。

2026-11-09のDebug環境では、1,500行×2列のSQL結果で初期生成7行、更新準備4.0ms、初回レイアウト39.4msを確認。環境・キャッシュ状態で変わる参考値で、改修前との同条件比較や描画フレーム時間を示すものではない。検証記録はartifacts/owner-responsiveness-verification.json。

## SQLの例

```sql
CREATE TABLE books (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    author TEXT,
    price REAL,
    available BOOLEAN DEFAULT TRUE
);

INSERT INTO books (id, title, author, price) VALUES
    (1, 'silverhamu入門', '猫山 まこと', 1800),
    (2, '小さなストアの設計', NULL, 2500);

SELECT id, title AS 書名, price
FROM books
WHERE price >= 2000 AND author IS NULL
ORDER BY id DESC
LIMIT 100;
```

```sql
BEGIN;
UPDATE books SET price = 2200 WHERE id = 1;
DELETE FROM books WHERE id = 2;
ROLLBACK;
SELECT * FROM books ORDER BY id;
```

BEGIN外では変更を文ごとに自動確定する。複数文を一括で取り消したい場合はBEGINを明示する。BEGIN / COMMIT / ROLLBACKボタンも同じトランザクションを操作する。全SQL文の構文を実行前に検査する。実行時エラーでバッチが途中停止した場合、先行文の確定済み変更は残り、メッセージに実行済みの文数を表示する。

## 対応構文

保存エンジン・TCP サービスと管理アプリの機能を比較するには、[silverhamu 本体と silverhamu Owner の SQL 構文マトリックス](../../README.md#sql-syntax-matrix)を参照。

|用途|対応内容|
|---|---|
|テーブル|CREATE TABLE、CREATE TABLE … AS SELECT、DROP TABLE、SHOW TABLES。ALTER TABLE で列の追加・改名・削除、互換性のある型への変更、DEFAULT・NOT NULL の設定と解除。|
|主キー索引|新規の主キー付きテーブルに自動作成。`REINDEX テーブル名` は主キーがあれば主キー索引を作成・再構築し、そのテーブルの一般列の索引もすべて再構築する。|
|一般列の索引|`CREATE INDEX [IF NOT EXISTS] 索引名 ON テーブル名 (列名[, 列名 …])`、`DROP INDEX [IF EXISTS] 索引名 ON テーブル名`。索引名はテーブルごとに管理する。|
|ビュー|CREATE VIEW、DROP VIEW、SHOW VIEWS。単一表の列を直接公開するビューは INSERT・UPDATE・DELETE に対応。|
|検索|SELECT *、列指定、AS、DISTINCT、CASE、CAST、算術式、定数 SELECT。|
|結合|最大8つの表またはビューを結合できる。ON には複合等価条件のほか、価格帯の比較や OR などの条件も指定できる。|
|書き込みとロック|通常のSQL接続では ON CONFLICT、RETURNING、TRUNCATE TABLE、行トリガーとシーケンスに対応。BEGIN 内で SELECT ... FOR UPDATE を使うと、取得した行を更新まで確保できる。[構文と制限](../../docs/sql.md#writes-and-concurrency)|
|実行計画|SQLデータベースとフォルダー閲覧で `EXPLAIN SELECT ...` を使える。`EXPLAIN ANALYZE SELECT ...` は各ステップの推定・実測行数、実行回数、経過時間（ms）を表示する。`ANALYZE テーブル名` で推定用の統計を更新する。|
|集計|GROUP BY、HAVING、COUNT(*)、COUNT(列)、COUNT(DISTINCT 列)、SUM・AVG・MIN・MAX。OVER で順位・集計・前後行の値を取得できる。|
|副問い合わせ|IN、EXISTS、スカラー・相関副問い合わせ、FROM の派生表。WITH、WITH RECURSIVE、UNION [ALL]・INTERSECT・EXCEPT に対応。|
|プロシージャー|CREATE PROCEDURE、EXEC / EXECUTE、DROP PROCEDURE。引数なし、本文は最大100文。|
|権限|GRANT / REVOKE でビューの SELECT と、表・ビューの INSERT・UPDATE・DELETE をロールごとに設定できる。|
|条件|比較、AND・OR・NOT、括弧、IS [NOT] NULL、LIKE、BETWEEN、IN (値リスト)。|
|並びと件数|ORDER BY、ASC / DESC、LIMIT / OFFSET、TOP、OFFSET … ROWS FETCH NEXT … ROWS ONLY。|
|挿入|INSERT INTO … VALUES の単一行・複数行と INSERT INTO … SELECT。|
|更新・削除|UPDATE の式による代入、DELETE、MERGE の条件付き更新・削除・挿入。|
|型|INTEGER、REAL、TEXT、BOOLEAN、BLOB|
|制約|単一列・複合 PRIMARY KEY、NOT NULL、UNIQUE、DEFAULT、CHECK、単一列・複合外部キー、ON UPDATE / DELETE CASCADE、TEXT / BLOB の長さ指定。|
|値・名前|文字列の''エスケープ、N'日本語'、NULL、TRUE/FALSE、X'00FF'、[引用名]、二重引用符の識別子|
|トランザクション|BEGIN / START TRANSACTION、COMMIT、ROLLBACK、SAVEPOINT、ROLLBACK TO SAVEPOINT、RELEASE SAVEPOINT。|
|スクリプト|セミコロン区切り、--行コメント、/*ブロックコメント*/|

INT/BIGINT、VARCHAR/NVARCHAR、FLOAT/DOUBLE/DECIMAL、BOOL、VARBINARYは対応する基本型の別名として扱う。INTEGERは符号付き64bit、REALは.NET decimalの範囲で扱う。暗黙の文字列→数値変換は行わない。テーブル名・列名は大文字小文字を区別しない。文字列の比較・LIKEは大文字小文字を区別し、ORDER BYの文字列順はOrdinal。NULLとの通常比較はUNKNOWNとなりWHEREでは選択されない。UNIQUEはNULLを複数許し、PRIMARY KEYはNULLを拒否する。

単一列の外部キーは主キー列または UNIQUE 列を、複合外部キーは複合主キーを参照する。ON UPDATE CASCADE と ON DELETE CASCADE は、参照先の変更を従属行と索引に同じトランザクションで反映する。

```sql
SELECT b.title, a.name AS author
FROM books AS b
INNER JOIN authors AS a ON b.author_id = a.id
ORDER BY a.name, b.title;
```

この例は `books(title, author_id)` と `authors(id, name)` を対象にする。結合キーの NULL は一致しない。外部結合では相手のない側の列に NULL が入る。各 JOIN の中間結果は最大4,096行で、WHERE・LIMIT を適用する前に上限を検査する。

ビュー定義は基底テーブルを参照し、JOIN・集計や射影を照会時点のトランザクションで評価する。定義内で別ビューや IN 副問い合わせを参照する機能はない。ビューの公開列や定義を壊す列変更と、参照先テーブルの削除は事前に拒否する。

一般列には `CREATE INDEX by_author_price ON books (author_id, price);` のように1〜64列の索引を作成できる。先頭列から等価条件で絞り、次の列の範囲条件を使える。例は `WHERE author_id = 42 AND price >= 1000`。対応する型のリテラルとの比較が対象で、取得候補は WHERE で再評価する。旧形式の一般列ハッシュ索引は `REINDEX books;` で順序付き索引に移行できる。索引付き書庫への書き込みには対応版のクライアントを使う。

```sql
CREATE TABLE books (title TEXT, public BOOLEAN, internal_note TEXT);
CREATE VIEW public_books AS SELECT title FROM books WHERE public = TRUE;
SELECT * FROM public_books;
```

たとえば管理者が `GRANT SELECT ON public_books TO reader;` を実行すると、reader として認証された利用者は `SHOW VIEWS` と `SELECT * FROM public_books` を使える。読み取りロールからの直接の表照会・生キー操作・更新は拒否する。ホストが利用者を認証する組み込みアプリでは、`QueryRoleViewAsync(sql, role)` またはビュー名の許可リストを取る `QueryPublishedViewAsync(sql, allowedViews)` を使用する。DB ファイルと管理者トークンは管理者側で保持する。

## 保存方式と上限

組み込み DB では共通の [SilverHamu.Sql](../../dotnet/SilverHamu.Sql) が Rust エンジンのトランザクション API を利用する。TCP では認証応答の SQL 能力に応じ、サーバーの SQL ホストまたはクライアントの共通実装が実行する。同じトランザクション DB と既存の Owner SQL カタログを読み書きする。[サービスおよび CLI の起動方法](../../docs/silverhamu-service.md)を参照。

テーブル定義は `_catdb_owner/sql/v1/table/<name hash>`、行は `_catdb_owner/sql/v1/row/<name hash>/<row id>` にJSONとして保存する。既存の生キー・値を自動でSQL表へ変換したり、削除したりしない。SQLデータの名前空間を生のキー値APIから直接変更しないこと。owner以外のクライアントがSQLを扱う場合も同じ形式と制約処理が必要。

- 256テーブル、1表64列、書き込み可能なSQLテーブルは1表4096行、結果64列。フォルダーの単一SELECT結果は全件取得後に100行ずつ表示する。
- 1行・テーブル定義はシリアライズ後256 KiB以下。
- 1回の表走査・1文の変更量は8 MiB以下。
- 1スクリプトは1 MiB・100文以下。
- 検索は索引に対応する等価・範囲条件で候補を取得し、適用できない条件では同じトランザクションでテーブルをページ走査する。上限を超えると部分結果を成功扱いせずエラーにする。

保存前に文全体の型・NULL・一意性を検査する。書込途中でサービスが拒否した場合は、途中の変更が残らないよう現在のトランザクション全体を取り消す。明示BEGIN中の場合は、それ以前の未確定変更も取り消される。検査段階だけのエラーでは明示トランザクションを維持する。確定応答を失った場合は自動再送せず、接続とデータの状態を照合する。

組み込み接続にはサービスの接続期限はなく、明示トランザクションは確定・取消・切断まで保持する。組み込みの資源上限は既存C#ラッパーの標準設定（変更32 MiB、読取依存16 MiB、保持128 MiB、バッファー16 MiB、最大64トランザクション）を使用する。

サービスの未使用接続期限は既定30秒、トランザクション保持期限は既定60秒。期限切れなどで切断された場合は再接続する。通信はTLSを内蔵しない。別ホストへ接続する場合は暗号化トンネルを使う。

### 結果表を編集してUPDATEをまとめて実行

テーブルの右クリックから「SELECT 1000行して編集」「SELECT 全行して編集」を選ぶと、上に結果表、下に更新SQLを置いた専用タブが開きます。セルのダブルクリック、F2、または「セルを編集」で、そのセルがテキストボックスに変わります。Enterまたはセル外への移動で変更を確定すると、下の欄にUPDATEを1文追加します。Escは入力の取消、Shift+Enterは改行です。

入力欄の横の「NULL」切替がオンならデータベースのNULL、オフなら入力値を使います。空文字と文字列の「NULL」も区別でき、NOT NULL列・主キーではNULL切替を無効にします。

下の「実行」を押すまでDBは変更しません。複数セルの変更は順番に実行し、各UPDATEがちょうど1行に一致しなければ全体を取り消してSQLを残します。生成したWHEREとRETURNINGは競合・重複行の検出に使います。既存トランザクション内ではSAVEPOINTを使い、反映後も外側のCOMMIT／ROLLBACKを待ちます。「結果を再取得」では未適用の変更を破棄するか確認します。ビューと読み取り専用接続は編集できません。

取得時の値と異なる未反映セルは琥珀色の背景・枠で示し、選択中も区別できます。ツールチップと読み上げ状態にも「DB未反映」を付け、SQL欄の上に未反映セル数とUPDATE文数を表示します。元の値まで戻したセルの色は解除します。

「元に戻す」「やり直す」、Ctrl+Z、Ctrl+Y（またはCtrl+Shift+Z）は、セルで確定した変更と下のSQL欄の編集に共通です。SQL入力中は短い入力のまとまりを履歴にします。セル内のテキストボックスを編集中は、そのテキストボックス内のUndo／Redoを使います。履歴はタブごとに保持し、実行成功・結果の再取得でリセットします。

下のUPDATE文を削除すると表を取得時の状態から再計算し、消した操作を巻き戻します。途中の生成UPDATEを消したときは、残った操作を実行できるよう後続のWHEREを自動調整します。SQLを書き換えた場合も、読み込み済みの1行を更新するSQLならプレビューに反映します。構文エラーや表示行に一致しないSQLは「SQLと未同期」と表示し、表は直前の有効な状態を保持してセル編集・実行を無効にします。SQLを修正するかUndoで復帰できます。

「行を追加」で表の末尾に緑色の追加予定行を作ります。行番号は「+1」などで示し、対応するINSERTにも同じ番号のコメントを付けます。既定値があれば入力済みとし、それ以外はNULLから始めます。必須列は「（必須）」と表示し、入力が済むまでは一括実行できません。追加行のセルを確定するたびに、その行のINSERTの値を更新します。

行番号またはセルを選んで「選択行を削除」またはDeleteキーを押すと、選択に含まれる行ごとにDELETEを追記します。既存行は赤色・取り消し線・「−」付きの行番号で残し、実行までDBからは削除しません。追加予定行の削除は、そのINSERTを取り消します。セル内の入力欄を編集中のDeleteキーは通常の文字削除です。

「選択行を複製」は、選択に含まれる削除予定でない行の現在値をコピーし、緑色の追加予定行と1行ずつのINSERTを作ります。表上部と右クリックメニューから操作できます。複数行の複製は1回のUndoで取り消せます。主キー・一意制約の列は値をコピーせずNULLへクリアします。複合主キーや複合・部分UNIQUE索引の参加列も対象で、通常の索引だけの列は値を保持します。複製直後は該当列に入力フォーカスを移し、必須列が未入力の間は実行できません。NULLを許可する一意列はNULLのままでも実行できます。既存の未反映セル変更や追加予定行の値も複製でき、複製後の編集は元の行へ影響しません。絞り込み中でも選択した行を複製し、複製後はフィルターを解除して新しい行を表示します。

行の追加・削除も同じUndo／RedoとSQL欄の削除に連動します。SQL欄からINSERTを消すと追加行が消え、DELETEを消すと削除予定が解除されます。INSERT・UPDATE・DELETEは順番に一括実行し、各文の変更件数が1行でなければ全体を取り消します。手入力は同じテーブルへの1行INSERTとWHERE付きUPDATE／DELETEが対象です。複数行のINSERT、INSERT SELECT、WHEREなしの削除、別テーブルへの変更、トランザクション操作は編集タブでは受け付けません。
